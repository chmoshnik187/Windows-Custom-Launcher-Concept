# DotShell: план перехода от «острова» к полноценному десктопу

**Статус:** подготовлен (грязная комната: анализ кодовой базы + синтез плана субагентами, 15.11.2026).  
**База:** локальный код **1.14.0** (последний опубликованный GitHub Release — `v1.12.0`), ветка/история по `main` в репозитории.  
**Источники:** `dotshell/ROADMAP.md`, `ПЛАН.md`, `ПАМЯТЬ.md`, `docs/RESEARCH.md`, `README.md`, `CHANGELOG.md`, структура `src/DotShell.Core` и `src/DotShell.Island.Wpf`, аудит кода субагентом (explore).

> **Вывод на момент запроса:** отдельного *полного, детального* плана миграции «остров → полноценный десктоп» ранее не было. Существовали канонический `ROADMAP.md` (этапы 1–5), рабочий `ПЛАН.md`, память проекта и исследования — но не целевой документ с фазами, архитектурой, критериями приёмки и стратегией сосуществования/замены Explorer. Этот документ закрывает разрыв и является рабочей основой для декомпозиции в задачи.

## 0. Текущее состояние (срез)

- **Архитектура:** `DotShell.Core` (UI-независимая логика: настройки, ThemeBus, DotGrid, медиа/SMTC, буфер, хоткеи, Win32, индексы, уведомления, обои/расписание, темы, обновления и др.) + `DotShell.Island.Wpf` (все поверхности: остров, виджеты, док, обзор, центр управления, лаунчер, настройки, трей, темы/обои-окна). Точка входа — `Program.cs` (single-instance, флаги, self-test/update hooks, exception logging) → `DotShellApp` → `ShellServices.InitializeAsync()` → `IslandWindow` + фоновые сервисы.
- **Реализовано (ключевое):** остров (капсула/раскрытие, вкладки, quiet/DND DotShell, уведомления), док (лево/право, auto-hide/peek, drag, закрепы), виджеты на рабочем столе + витрина (в т.ч. умная папка 3.1), dashboard/control center, лаунчер/поиск (приложения+файлы), темы 4.1 (движок/ThemeSpec/ThemeStore/ApplyTheme|ApplySkin, пикер), обои по времени 3.4, зеркалирование системных уведомлений (1.8), обновления через GitHub Releases + self-update.
- **Проверки (локально, этот прогон):** `dotnet build` 0/0, `smoke` PASS (1.14.0), `ui-audit -Quick` 5/5 (включая `--theme`), `widget-audit -Quick` 5/5.
- **Известные ограничения/хвосты:** мультимонитор/per-monitor геометрия не доведена до end-to-end (A.3, D.2.4 `[~]`), реальная проверка на 2+ мониторах/разных DPI недоступна в текущей среде (1 монитор, ~125% DPI); безопасного уменьшения publish нет (A.12 `[~]`); 2.3 менеджер окон, 4.2 плагины, 4.3 макросы, 5.1 замена explorer — не начаты/рискованны.

### 0.1 Ключевые архитектурные факты и ограничения (из аудита кода)
- **Нет shell-хоста/замены Explorer:** приложение — overlay-процесс рядом с Explorer (`OnExplicitShutdown`, кастомный трей, top-level окна). Нет регистрации shell, владения рабочим столом, taskbar-замены, shell namespace.
- **Виджеты — отдельные окна, не управляемый desktop-layer:** `WidgetWindow` (toolwindow, no-activate опционально, `SendToDesktopLayer`-поведение best-effort), координаты/раскладка сохраняются, но нет единой per-monitor политики Z-order/композиции под окнами в терминах shell.
- **Геометрия смешанная:** island использует `SystemParameters.WorkArea` и `VirtualScreen` (кламп), док/виджеты учитывают DPI/монитор точечно; полноценная per-monitor модель и hot-plug миграция не завершены.
- **Интеграции с Explorer эвристические/инвазивные:** скрытие иконок (`SysListView32` под `Progman/WorkerW`), перекраска ярлыков `.lnk`, открытие в табах через синтез клавиш/буфер — хрупко к обновлениям Windows/рестартам Explorer.
- **Ограничения платформы:** системный Focus/DND без MSIX identity недоступен (DotShell DND — честный режим); часть API (радио, гамма/night light, brightness) device/driver-dependent.
- **Обновления:** проверка релизов GitHub, self-update со staged exe + `--version-probe` + `.old` откат; без криптоподписи/хэша ассета в коде (доверие релизу/HTTPS).

## 1. Видение и определение: «полноценный десктоп» для DotShell

### 1.1 Критерий готовности
«Полноценный десктоп» = пользователь может **постоянно работать в сессии Windows, опираясь на DotShell как на основной визуальный и навигационный слой**, сохраняя доступ к: рабочей поверхности (обои + интерактивные объекты/виджеты), запуску и поиску (приложения/файлы/настройки/действия), панели задач/дока и системным статусам (сеть/звук/питание/уведомления), управлению окнами (фокус, снаппинг, базовые сценарии), персонализации (тема/акцент/обои/раскладки) в едином визуальном языке, и корректной работе на нескольких мониторах и DPI.

**По умолчанию — сосуществование с Explorer** (файловый менеджер и часть shell-инфраструктуры остаются системными). Полная замена `explorer.exe` — отдельный opt-in режим (этап 5.1 ROADMAP), не критерий базовой «готовности».

### 1.2 Области и целевое состояние

| Область | Цель | База сейчас | Остров остаётся? |
|---|---|---|---|
| **Desktop canvas** (слой рабочего стола) | Управляемая поверхность: виджеты «на обоях» под окнами, сетка/привязка, per-monitor раскладки, стабильный Z-order/focus-policy | Виджеты-окна, расписание обоев, best-effort desktop layer | Нет — ядро десктопа |
| **Панель задач / Shell Bar** | Эволюция дока: закрепы + запущенные окна, индикаторы, переключение/группировка (этапно), системная область — честно | Док (край, peek, закрепы, индикатор запуска) | Остров — быстрый хаб, не замена бара |
| **Старт / лаунчер** | Единый вход: приложения, файлы, настройки, действия, недавние; хоткей/бар/остров | Поиск приложений+файлов, лаунчер, pinned-группы | Капсула может вызывать старт, не заменяя полноформатный UX |
| **Виджеты** | Зрелая система: пер-монитор, профили, производительность, витрина, данные | Набор виджетов, адаптивность, умная папка, хранение в `widgets.json` | — |
| **Уведомления и центр управления** | Единый inbox/центр + быстрые тумблеры/статусы, дедупликация, честная деградация | Режимы показа, зеркалирование тостов, Control Center, DotShell DND/night light | Капсула — компактный peek; центр — полноформатный |
| **Управление окнами** | Снаппинг/зоны, хоткеи, базовые правила (без инжекта/DWM-патчей); виртуальные столы — позже | Нет (2.3), есть фокус-шторки/карта окон/детекторы | — |
| **Темы и визуал** | Полный цикл: превью/пикер/импорт-экспорт/валидация/миграции, покрытие всех поверхностей | Движок 4.1, ThemeSpec/Store, пикер, DotGrid/токены motion | — |
| **Файлы / умные папки** | Интеграция с desktop-layer, поиск/лаунчер, профили раскладок | Умная папка 3.1 (правила/порталы/Undo/async/watcher) | — |
| **Мультимонитор и DPI** | Per-monitor модель, hot-plug, смешанный DPI, сохранение раскладок | Частично (virtual-screen clamp, точечные DPI-фиксы) | — |
| **Обои** | Единый пайплайн (статика/расписание/источники), акцент, (позже) профили по мониторам | Расписание 3.4, акцент/Windows accent | — |

### 1.3 Non-goals (на горизонте)
- Патч системных DLL, инжект в чужие процессы, собственный композитор/DWM.
- Обязательная замена Explorer для «готовности» десктопа.
- Обещание «настоящего» системного DND/Focus без MSIX identity.
- Плагины до стабилизации API/контрактов (после 4.1 и уточнения архитектуры).

### 1.4 Явные допущения
- Платформа: Windows 10/11 x64, .NET 8, WPF; правило `Core` не зависит от UI сохраняется.
- Данные/конфиги: `%LOCALAPPDATA%\DotShell\` (`settings.json`, `widgets.json`, `pinned.json`, `folder-portals.json`, `wallpaper-schedule.json`, `themes/`, логи) с версионированием и бэкапами при миграциях.
- Метод «грязная/чистая комната» (R.1): чужие идеи изучаются, реализация своя, без копирования кода/ассетов.

## 2. Целевая архитектура

### 2.1 Принципы
- **Core/UI разделение**, единые шины (`ThemeBus`, события настроек), единая модель мониторов/раскладок.
- **Feature flags и режимы** (`shellMode`, `desktopHostEnabled`, `shellBarMode`, `startLauncherEnabled`, `windowManagerEnabled`, `notificationCenterUnified`, `perMonitorLayouts` — имена уточнить).
- **Честная деградация** и явные статусы ограничений.
- **Инкрементальность и откат:** каждая фаза ценна сама по себе, дефолт не ломает island-only.

### 2.2 Логические модули (расширение текущей структуры)

| Слой | Компонент | Ответственность | Ориентир сейчас |
|---|---|---|---|
| Core: Desktop | `DesktopLayoutService` | Per-monitor раскладки виджетов/поверхностей, профили, миграции | `Widgets/WidgetStore`, `Windowing/Monitors` |
| Core: Shell | `ShellModeService` | Режимы island/coexist/replacement(opt-in), capabilities | `Settings/AppSettings`, `StartupManager` |
| Core: Launcher | `LauncherService` + провайдеры | Apps/files/settings/actions/recents, ранжирование, кэш | `Launcher/AppIndex`, `FileIndex`, `Settings/SettingsCatalog` |
| Core: Windows | `WindowModelService` | Модель окон, состояния, группировка, команды | `Windowing/*`, `Launcher/ProcessProbe` |
| Core: WM | `SnapEngine` / `WindowRules` | Снап-зоны, хоткеи, правила (без инжекта) | `Windowing/*`, `Native/Win32`, `Input/HotkeyManager` |
| Core: Notify | `NotificationCenterService` | Нормализация, дедуп/AUMID, история, фильтры | `Notifications/SystemNotificationWatcher` |
| Core: Theme | `ThemePipeline` | Валидация/миграция ThemeSpec, применение/превью/откат | `Theming/*` |
| UI: Desktop | `DesktopHostWindow(s)` | Desktop-layer per-monitor, размещение виджетов, фон/hit-test | `Widgets/*`, новый `Desktop/` |
| UI: Bar | `ShellBar` (эволюция дока) | Закрепы, запущенные, индикаторы, (этапно) системная область | `DockWindow` |
| UI: Start | `StartLauncherWindow` | Полноформатный старт/поиск | `LauncherWindow` |
| UI: Control/Notify | `ShellControlCenter`, `NotificationCenterView` | Статусы и уведомления, связка с островом | `ControlCenterWindow`, `IslandWindow.Notifications*`, `NotificationHub` |
| UI: WM | `SnapOverlay` | Визуализация зон/подсказки | новый overlay |

### 2.3 Ключевые потоки
- **Тема/обои/акцент:** источник → `ThemePipeline/ThemeBus` → все поверхности; откат через снимки/предыдущее состояние.
- **Раскладки:** `DesktopLayoutService` ↔ `widgets.json` (vNext) → host/manager per-monitor.
- **Поиск/запуск:** ввод → провайдеры (параллельно, лимиты) → ранжирование → действие.
- **Окна/бар:** `WindowModelService` (enum/hooks + троттлинг/poll fallback) → модель → `ShellBar`.
- **Уведомления:** watcher → нормализация/фильтр → центр/остров/история.
- **WM:** хоткей/drag → `SnapEngine` (координаты монитора) → `SetWindowPos`/DWM bounds (осторожно) → overlay.

### 2.4 Миграции и совместимость
- Версионировать схемы `settings.json`, `widgets.json`, `pinned.json`, порталов/тем; идемпотентные миграции + `.bak` + лог (паттерн A.2).
- При выключенных флагах — поведение идентично текущему. Старые конфиги читаются без потери данных.

| **D4. Уведомления и контроли** | Единый центр/история, связка остров↔центр, честные статусы | P1 | M | watcher, ControlCenter, UI острова |
| **D5. Управление окнами (MVP)** | Снаппинг/зоны/хоткеи, overlay, базовые правила (opt-in, риск) | P1 | L | D0, Win32, модель окон |

| **D7. Coexist/Explorer (opt-in)** | Профиль сосуществования как дефолт; replacement — исследование/sign-off, откат | P1/P2 | L | D1–D4 зрелость, надёжный старт/обновление |
| **D8. Надёжность и готовность** | Перф-бюджеты, multi-monitor/DPI sign-off, восстановление, доки, релизная полировка | P0 | M | все включённые фазы |

### Критерии приёмки по фазам (сокращённо)

- **D0:** остров/док/центры корректно позиционируются при смене рабочей области/DPI (чек-лист; мультимонитор — verified/blocked), `smoke` и `ui-audit -Quick` стабильны последовательно, новые настройки в `SETTINGS.md`, флаги/миграции с бэкапом.
- **D1:** виджеты стабильно под окнами без кражи фокуса/Alt+Tab, раскладка per-monitor сохраняется/восстанавливается, graceful fallback при hot-plug, `widget-audit` расширен кейсами desktop-host.
- **D2:** релевантный поиск apps/files/settings/действий в целевом бюджете отзывчивости, недавние/закрепы сохраняются, аккуратные пустые/ошибочные состояния.
- **D3:** запущенные окна отражаются для типовых Win32/UWP сценариев (чек-лист), переключение/минимизация без регрессий фокуса/геометрии, нет утечек/роста idle CPU; fallback на док.
- **D4:** ключевые режимы покрыты аудитом, история без некорректного реплея/дублей (AUMID/id), неподдерживаемые действия объяснены в UI.
- **D5:** снаппинг на основных сценариях (1 монитор, стандартные DPI) без застреваний, полный откат флагом/перезапуском, «panic disable».
- **D6:** импорт/экспорт/превью согласованы, валидация/миграции тем, покрытие остров/бар/host/виджеты/окна.
- **D7:** coexistence не ухудшает Explorer; replacement только opt-in с документированным safe-mode/откатом (не дефолт).
- **D8:** пройдены целевые аудиты и multi-monitor/DPI матрица, перф-бюджеты соблюдены, island-only без регрессий, ограничения задокументированы.

### Риски и митигации (сквозные)
- **Z-order/фокус desktop host:** спайк хостинга, режимы совместимости, kill-switch, лимиты обновлений.
- **Мультимонитор/смешанный DPI:** единая модель координат/монитора, defensive clamp, обязательная живая матрица перед sign-off.
- **Нестабильность window enumeration/hooks:** гибрид events+polling с троттлингом, фильтры, fallback.
- **Конфликты WM (PowerToys/FancyZones/системный snap):** opt-in, детект/disable, panic hotkey.
- **Explorer-хрупкость (иконки/табы):** изоляция фич, best-effort, быстрый откат, не требовать для базового сценария.
- **Обновления/релизы:** обновление только через GitHub Releases; `release.ps1` + probe; при неудаче автозапуска — подхват при следующем старте (уже реализовано).

**Верификация:**
- **Каждый срез:** `dotnet build`, `smoke.ps1`, при затронутом UI — `ui-audit`/`widget-audit`/профильные аудиты **последовательно**.
- **Схемы/настройки:** проверка миграций (старый→новый, битый файл → `.bak`+fallback), `sync_settings_docs.py --check`.
- **Мультимонитор/DPI:** обязательный ручной чек-лист (1–2+ монитора, 100/125/150%, смешанный DPI, hot-plug, смена primary) перед sign-off D0,D1,D3,D5,D8; автотесты где применимо.

- Нестабильные в окружении тесты фиксировать как `blocked-by-env` с логом.

## 6. Стратегия релизов и инкрементальной поставки

- **Island-first совместимость:** режим «как сейчас» остаётся рабочим и дефолтным до явного включения desktop-функций/профиля.
- **Feature flags:** независимое включение/откат desktop host, shell bar mode, start, WM, unified notifications.
- **Миграции:** только вперёд-совместимые чтения на старте, бэкапы, логирование.
- **Обновления только через GitHub Releases** (факт доставки пользователю = опубликованный релиз с assets), релизный пайплайн `scripts/release.ps1` + `--version-probe`.
- **Чек-лист релиза:** build 0/0, `smoke` PASS, релевантные аудиты PASS (или `blocked-by-env` с логом), миграции проверены, `SETTINGS.md` синхронизирован, `CHANGELOG/ROADMAP/ПЛАН/ПАМЯТЬ` обновлены, фичи под флагами задокументированы, rollback-процедура описана.
- **Предлагаемые вехи:** M1 (D0 база/флаги/аудиты) → M2 (D1 desktop host opt-in) → M3 (D2 start v1) → M4 (D3 shell bar taskbar-lite opt-in) → M5 (D4+D6 консистентность) → M6 (D5 WM MVP opt-in) → M7 (D7/D8 coexistence polish + opt-in replacement research).
