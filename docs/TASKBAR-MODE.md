# Остров внутри панели задач: как это работает

> Выжимка «чистой комнатой» + проверки на живой Windows 11 26300. Здесь —
> как остров встроен в панель сейчас, почему выбран этот путь и что осталось
> за кадром.

## Коротко

Свёрнутый остров — **дочернее окно самой панели задач**: `SetParent` в
`Shell_TrayWnd`, `WS_CHILD`, своя область-клип по свободному пробегу. Это не
оверлей поверх панели: панель сама двигает окно, обрезает его и прячет вместе
с собой. Никаких инъекций в explorer, никакого Windhawk, никаких отдельных
установок — всё внутри одного `DotShell.exe`.

Реализация — `Deskband11Lib.Wpf` 1.5.1 (MIT, см. `THIRD-PARTY-NOTICES.md`) +
наш `TaskbarIslandHostWindow`.

## Почему именно так, а не иначе

| Подход | Примеры | Вердикт |
|---|---|---|
| Дочернее окно панели (`SetParent`) | Deskband11, Deskband11Lib, EverythingToolbar v3 | **Взят.** Работает на штатной панели, без инъекций; панель не резервирует место, но окно живёт в её свободном пробеге и переживает перемещение панели |
| Инъекция в explorer / XAML | Windhawk Island Media Controls, Taskbar Widgets, StartAllBack | Настоящая «встроенность в раскладку» (панель резервирует место), но нужен отдельный код в explorer/Windhawk и хрупко к обновлениям Windows |
| AppBar | Seelen UI, MyDockFinder | Своя панель/кромка, не «внутри виндовой панели» |
| Полная замена панели | Seelen UI | Месяцы работы: кнопки, трей, флайауты |

Важный вывод из исследования: **панель задач Windows 11 — XAML-поверхность,
и третье приложение не может «вписаться в её раскладку» без кода в explorer**.
Но визуально и поведенчески быть её частью можно child-окном — именно так
делают EverythingToolbar (поиск в панели), TrafficMonitor и Deskband11Lib.

## Что проверено на этой машине (build 26300, 3440×1440, 125%)

- дочернее окно внутри `Shell_TrayWnd`: `rect=198,1380 550×60`, `IsWindowVisible=true`;
- большое окно острова в свёрнутом виде скрыто — двойника нет;
- клик по встроенному острову открывает панель **975×765 над панелью задач**;
- клик мимо — сворачивает и прячет большое окно, **остров остаётся в панели**;
- кликабельные цифры столов внутри острова переключают виртуальные столы
  (`index 0 ↔ 1`), панель после этого на месте;
- уведомление при свёрнутом острове — капсула над панелью `634×63`, не карточка
  в углу;
- клик по обоям запускает рябь; клик по панели задач — нет;
- док: окно программы минимизируется/восстанавливается/закрывается через
  документированный Win32 (проверено отдельным harness), зависшие окна не
  блокируют док.

## Что происходит при сбое

- если `AttachWhenLayoutReadyAsync` не смог встроиться (нестандартная панель,
  удалённый сеанс) — включается прежний оверлей-режим: остров остаётся видимым,
  просто не является child-окном;
- при перезапуске explorer / отключении монитора / смене DPI библиотека поднимает
  `TaskbarWindowRecreationRequired` — окно пересоздаётся и встраивается заново;
- elevated-окна (UIPI) не трогаем: действия с ними Windows молча игнорирует.

## Ограничения

1. Панель не «резервирует» место: окно встаёт в свободный пробег (как
   EverythingToolbar). При полностью забитой панели места может не хватить —
   тогда остаётся фолбэк.
2. Встроен только основной `Shell_TrayWnd`; вторичные панели мониторов пока
   обрабатываются оверлеем (в планах).
3. Рябь «под иконками» на 24H2+ требует отдельного D3D11/DirectComposition
   helper — текущая рябь рисует над обоями, но пропускает клики.

## Что можно сделать дальше

1. Вторичные панели (`Shell_SecondaryTrayWnd`) и вертикальные позиции 26H2 —
   добавить `PreferredMonitorIdentity` по мониторам.
2. Опциональный XAML-мод через Windhawk (не требуется для базовой работы) —
   если захочется, чтобы панель реально сдвигала кнопки под остров.
3. D3D11-helper для ряби строго под иконками.
