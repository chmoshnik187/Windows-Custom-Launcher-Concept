# ROADMAP — что уже есть и что делать дальше

Здесь честно: что написано в скелете, что оно делает, и следующие шаги —
маленькими кусками, каждый из которых заканчивается чем-то работающим.

---

## ✅ Сделано в скелете

### Ядро (`src/DotShell.Core`)

| Модуль | Файл | Что умеет |
|---|---|---|
| Win32-слой | `Native/Win32.cs` | все нужные объявления: стили окон, DWM, мониторы, буфер, хоткеи |
| Невидимое окно | `Native/NativeMessageWindow.cs` | принимает системные сообщения (буфер обмена, горячие клавиши) |
| Настройки | `Settings/AppSettings.cs`, `SettingsStore.cs` | типизированные настройки, атомарная запись в JSON |
| Шина темы | `Theming/ThemeBus.cs` | единый акцент для всех модулей + плавное сглаживание |
| Подбор цвета | `Theming/ColorExtractor.cs` | картинка → акцент + палитра из 5 цветов, с «уверенностью» |
| Авто-цвет | `Theming/AccentSampler.cs` | кадр рабочего стола → ThemeBus; игнорирует свои окна; не работает в fullscreen |
| Формат темы | `Theming/ThemeSpec.cs` | схема `theme.json`: цвета, точка, анимации, виджеты |
| **Точечный движок** | `DotMatrix/DotGrid.cs` | `Sample` (пиксели → сетка яркостей) и `Rasterize` (сетка → кружки). Ядро всей эстетики |
| Буфер обмена | `Clipboard/*` | история, дедупликация, пины, fuzzy-поиск, картинки в PNG |
| Медиа | `Media/MediaBridge.cs` | SMTC: трек, артист, обложка, позиция, play/pause/next/prev/seek |
| Хоткеи | `Input/HotkeyManager.cs` | глобальные сочетания через `RegisterHotKey` |
| Вставка | `Input/SendKeys.cs` | эмуляция Ctrl+V в чужое приложение |
| Окна | `Windows/WindowWatcher.cs` | детектор fullscreen (игры/видео), точные границы окон для будущего «заплывания» |
| Телеметрия | `SystemStats.cs` | CPU / батарея / память без тяжёлых зависимостей |
| Автозапуск | `StartupManager.cs` | ключ Run в HKCU |

### Остров (`src/DotShell.Island`)

| Модуль | Файл | Что умеет |
|---|---|---|
| Точечный текст | `Controls/DotTextBlock.cs` | **любой текст любым шрифтом → сетка точек**. Работает через скрытый TextBlock + RenderTargetBitmap + DotGrid |
| Часы | `Controls/DotClockControl.xaml(.cs)` | ЧЧ:ММ точками, мигающее двоеточие, обновление текста только при смене минуты |

| Сервисы | `ShellServices.cs` | композиционный корень |

### Инструменты
- `tools/theme_from_image.py` — тема из картинки (тот же алгоритм подбора цвета, на Python).
  Работает **без зависимостей** для PNG, для jpg/webp нужен Pillow.
- `tools/make_icon.py` — генератор иконки (чистый Python, пишет .ico вручную).
- `themes/example-nothing-red.json` — образец темы.

## 🔜 Шаг 1. Заставить это собраться и поехать (0.5–2 дня)

Цель: увидеть остров на своём экране.

1. Поставить Visual Studio 2022 Community + workload .NET + WinUI 3 (см. README).
2. Открыть `DotShell.sln`, выбрать x64, собрать.
3. **Починить ошибки сборки, если будут.** Это ожидаемо: код написан без компилятора.
   Каждую ошибку — в `docs/TROUBLESHOOTING.md`, там уже разобраны типовые.
4. Запустить, убедиться что:
   - таблетка появилась сверху по центру;
   - часы идут и мигает двоеточие;
   - клик раскрывает остров;
   - при включённой музыке виден трек и работают кнопки;
   - `Ctrl+Shift+V` открывает вкладку буфера, скопированный текст там появляется;
   - во вкладке «Тема» пресеты перекрашивают всё сразу.

**Критерий готовности шага:** ты этим пользуешься. Не «запустил и закрыл», а оставил висеть.

## 🔜 Шаг 2. Лаунчер (1–2 недели)

Самая полезная следующая штука: после неё шеллом начинают пользоваться руками.

1. Новый проект `src/DotShell.Launcher` (WinUI 3, то же ядро).
2. Индекс приложений:
   - `.lnk` из `%APPDATA%\Microsoft\Windows\Start Menu\Programs` и
     `%ProgramData%\Microsoft\Windows\Start Menu\Programs` — читать через `IShellLink`;
   - UWP-пакеты — `Windows.Management.Deployment.PackageManager`;
   - иконки — `SHGetFileInfo` / `StorageFile.GetThumbnailAsync`.
3. Поиск: **переиспользовать** `InMemoryClipboardHistory.FuzzyScore` — он уже написан.
   Вынести его в `Core/Search/FuzzyMatcher.cs`, чтобы буфер и лаунчер делили один алгоритм.
4. Иконки в точках: `StorageFile` → битмап → `DotGrid.Sample` → `DotGrid.Rasterize`.
   Это буквально 20 строк, движок уже готов.
5. Хоткей `Ctrl+Space` (или `Alt+Space`), окно появляется у курсора и исчезает по Esc.

**Подсказка по срокам:** если хочешь быстрее — поставь Flow Launcher и напиши ему тему.
Свой лаунчер делай, когда захочется точечных иконок и единого стиля.

## 🔜 Шаг 3. Тема-паки и импорт/экспорт (3–5 дней)

Сейчас `ThemeSpec` описан, но не применяется.

1. `ThemeLoader`: прочитать JSON → заполнить `AppSettings` + вызвать `ThemeBus.SetAccent`.
2. Папка `%LOCALAPPDATA%\DotShell\themes\` — сканировать при старте, список во вкладке «Тема».
3. Экспорт текущей темы в файл (кнопка «Сохранить как…»).
4. Live-preview: при наведении на тему в списке — акцент меняется, при уходе — возвращается.
5. Потом: `.zip` вместо `.json`, внутрь кладутся глифы, иконки и сцена обоев.

## 🔜 Шаг 4. Свои обои и «заплывание» (самая дорогая часть)

Делать ПОСЛЕ того, как островом и лаунчером уже приятно пользоваться.

**4a. Сначала дешёвый путь (1 неделя):**
не писать свой движок — управлять Lively Wallpaper (у него есть IPC/CLI),
а из своего кода отдавать ему сцену из темы. Авто-цвет при этом берётся
не со скриншота, а напрямую из кадра сцены — точнее и дешевле.

**4b. Потом «подсветка» вместо «заплывания» (1 неделя):**
тонкая акцентная кромка/свечение вокруг окна в фокусе. Один тонкий оверлей
по периметру `TryGetExtendedBounds` — копейки по производительности,
а выглядит как раз «лампово».

**4c. И только потом настоящее «заплывание» (3–6 недель, экспериментально):**
слой поверх окон с дырками по прямоугольникам окон.
- `EnumWindows` + `DWMWA_EXTENDED_FRAME_BOUNDS` → список rect'ов;
- обновление по `EVENT_OBJECT_LOCATIONCHANGE` (WinEvent hook), а не опросом;
- маска через `UpdateLayeredWindow` или Composition;
- 30 fps cap, пауза при батарейном питании, whitelist окон;
- **обязательно за тумблером** с предупреждением про расход батареи.

## 🔜 Шаг 5. Эквалайзер по-настоящему (1–2 недели)

1. Пользователь ставит Equalizer APO (бесплатно, open source).
2. DotShell генерирует его `config.txt` из своих пресетов (текстовый формат, простой).
3. Вкладка EQ перестаёт быть визуализацией: полосы рисуются по реальным коэффициентам,
   пресеты переключаются записью конфига + перезапуском APO-сервиса.
4. Если защищённый поток (DRM) — показать плашку «EQ недоступен для этого приложения».

## 🔜 Шаг 6. То, что превращает набор программ в продукт

- ✅ Автозапуск вместе с Windows — **уже есть** (тумблер во вкладке «СИСТЕМА»,
  ключ `HKCU\...\Run`, флаг `--minimized` для тихого старта).
- ✅ Скрипт установщика — **уже написан** (`installer/DotShell.iss` для Inno Setup 6,
  собирает `build.bat installer`). Осталось только поставить Inno Setup и собрать.
- ✅ Переносимая сборка без установки — **уже есть** (`build.bat publish`).
- Иконка в трее + контекстное меню (H.NotifyIcon или свой Win32 NotifyIcon) —
  сейчас выйти можно только кнопкой «ВЫЙТИ» внутри острова, и это неудобно.
- SQLite для истории буфера и заметок (сейчас память + .md — намеренно).
- Подпись бинарников (иначе SmartScreen будет пугать людей).
- Профили: «работа» / «ночь» / «игра» — разные наборы виджетов, переключение по хоткею.
- Multi-monitor: выбор монитора для острова, разный DPI.
- Автообновление (проверка версии на GitHub Releases при старте).

## Как оценивать свой прогресс

Не «написал N строк», а три вопроса после каждого шага:

1. **Пользуюсь ли я этим сам каждый день?** Если нет — фича не нужна, какой бы красивой ни была.
2. **Сколько памяти и CPU это стоит в простое?** Диспетчер задач → Details → DotShell.Island.exe.
   Цель: < 250 МБ и < 1% CPU. Если больше — ищи таймер, который тикает без нужды.
3. **Переживёт ли это обновление Windows?** Всё, что опирается на недокументированное
   (WorkerW, инжект), обязано иметь fallback и не ронять остальное.

## Что НЕ надо делать (проверено чужими граблями)

- **Не патчить `uxtheme.dll`** ради «настоящих» тем. Неподписанные системные файлы,
  поломка после каждого апдейта, риск для пользователя.
- **Не делать DLL-инжект в чужие процессы** в основном продукте. Только как отдельный
  опциональный мод с большим дисклеймером.
- **Не подменять системные шрифты через реестр глобально.** Точечный шрифт в системном
  диалоге — это не стильно, это опасно.
- **Не писать свой аудио-движок (APO).** Equalizer APO уже существует.
- **Не строить монолит.** Как только появится третий тяжёлый модуль — разъезжай на процессы.
- **Не делать Electron.** 24/7 процесс на 400 МБ ради часов из точек — нет.

## Записано со слов владельца (ждёт своей очереди)

- **Варианты оформления (скины):** по ~10 разных видов на каждую вкладку и на свёрнутый
  остров — абсолютно разные, не только цвета. Вводить, когда возьмёмся за полноценное
  оформление Windows: формат темы расширится до "скин-пакета".
- **Плавное открытие/сворачивание окон как на macOS.** Технически достижимо:
  SetWinEventHook на создание/минимизацию окон + собственная анимация-обманка
  (DWM-thumbnail или оверлей-дублёр). Средней хрупкости: слежение за окнами переживает
  не каждый апдейт Windows. Оцениваемо как отдельный модуль "window manager".
- **Авто-цвет из обоев Wallpaper Engine / Lively.** Уже совместимо по построению:
  сэмплер берёт цвет с готовых пикселей экрана, поэтому источник обоев (системные,
  Wallpaper Engine, Lively) не важен. Отдельной работы не требует — проверить на живых
  примерах.

## ✅ 0.4.0 — остров становится шеллом (выпущено)

Владелец спросил: «лаунчер — это то, что переделает оформление винды под стандарт
острова, а не поисковая строка». Согласны. Вот первые настоящие шаги в эту сторону:

- **Главная страница** (вкладка ⌂): трек, громкость системы, инструменты
  (тема Windows, иконки стола, виджеты, лок, сон) и панель «МОИ ПРОГРАММЫ».
- **Плитки «мои программы»**: закрепление из индекса меню «Пуск» (плитка «+»,
  нечёткий поиск) или правым кликом в лаунчере; список в pinned.json,
  иконки кешируются в icons/; клик — запуск, правый клик — убрать/папка.
- **Виджеты рабочего стола**: часы из точек, эквалайзер, плеер, система (CPU/RAM),
  юниты. Трей → «Виджеты на рабочем столе» или кнопка ВИДЖЕТЫ на главной.
  Таскаются мышью, раскладка в widgets.json, не мелькают в Alt+Tab, не крадут фокус,
  не topmost (живут НА столе, под окнами).
- **Скрытие иконок рабочего стола**: тумблер в СИСТЕМА и кнопка на главной
  (Progman → SHELLDLL_DefView → SysListView32, без реестра и перезапуска Explorer).
- **Чат растёт вместе с перепиской**: остров вытягивается к нижнему краю экрана,
  дальше — прокрутка. Раньше высота задавалась один раз при раскрытии.
- **Вкладка EQ снята** по просьбе владельца: мини-эквалайзер под пилюлей справляется сам.
- **Громкость колесом мыши** над свёрнутой пилюлей + чип VOL на секунду.

Дальше по направлению «шелл»: живые обои + «протекание» на окна, скин-паки
(≈10 видов оформления на вкладку), анимации окон как на macOS.
Центр управления (Wi-Fi/BT/VPN) по-прежнему отложен: админ-права и API адаптеров.

## ✅ 0.5.0 — пакет «полезные виджеты» (выпущено)

Владелец принёс список из 20 сгенерированных идей; после честного разбора

  дата последней установки; кнопки ведут в системные страницы (пауза без админа

- **Карта окон** (виджет): EnumWindows с фильтрами таскбара, снимок PrintWindow

- **Фокус-шторки**: одно click-through-окно на виртуальный экран с дырой по
  активному монитору (EnumDisplayMonitors + GetDpiForMonitor).
- **HUD хоткеев**: WH_KEYBOARD_LL, плашка с шорткатами активной программы;
  база HotkeyCatalog + слияние с hotkeys.json владельца.

## ✅ 0.6.0 — аудио-роутер и обновления (выпущено)

- **Аудио-роутер** (виджет). Маршрутизация звука по приложениям через
  `IAudioPolicyConfigFactory` (`Windows.Media.Internal.AudioPolicyConfig`):
  `SetPersistedDefaultAudioEndpoint` для роли Multimedia и Console, device-id
  в формате `\\?\SWD#MMDEVAPI#…#{e6327cad-…}`. Плюс перечисление устройств
  и сессий (NAudio) и громкость каждого приложения через `ISimpleAudioVolume`.
  Проверено на живой Windows 11: приложение действительно меняет устройство,
  настройка сохраняется между сессиями, «сбросить на системное» работает.
  Важная деталь: WinRT-маршалинг (`HString`, `InterfaceIsIInspectable`) в WPF
  не поднимается, поэтому HSTRING создаётся руками через combase, а интерфейс
  берётся как обычный COM с тремя пустыми слотами IInspectable в начале.
- **Проверка обновлений**: GitHub Releases API → сравнение версий →
  пузырь над треем + пункты меню. Скачивание и подмена exe сознательно
  оставлены человеку: авто-замена живого файла — отдельная задача с
  собственными граблями.

- **Эквалайзер**: градиент хвоста, опадающие пики, вызов `UpdateMiniEq` на тике.
- **Починено**: заметки поверх главной на старте (общий `ShowTab`), падение
  `ExpandAndGoToTab` на `Cast<RadioButton>`, флаг `--tab=`.

## 🔜 Дальше по плану (после 0.7.0)

Три вещи, которые владелец назвал сам, в порядке пользы:

1. **Скины и оформление вкладок** — по 10 вариантов на вкладку и на свёрнутую
   пилюлю. Инфраструктура уже есть: тема = один JSON, всё красится через
   `DynamicResource`, значит скин = набор ресурсов + флаг в `settings.json`.
2. **Живые обои и «протекание» на окна** — самое дорогое: нужен свой рендер
   за рабочим столом (окно-подложка под иконками) и аккуратное отключение в
   фуллскрине. Авто-цвет уже умеет читать любой источник пикселей, включая
   Wallpaper Engine.
3. **Настоящий установщик** вместо `install.bat` + авто-скачивание обновлений
   с заменой exe. Нужен, когда обновления станут частыми: один `.exe` вместо
   архива на 75 МБ каждый раз.

Дальше — по желанию: центр управления (Wi-Fi/BT/VPN, только с UAC),
системный EQ через Equalizer APO, скины рабочего стола.
