# Можно ли это построить на Windows

> Разбор потолков: где Windows пускает, где приходится обходить, а где честно не выйдет.

Состояние на **0.67.2**: часть разбора уже стала кодом, часть осталась теорией. Ниже
отмечено, что именно сделано, а что пока нет — чтобы документ не врал.

---

## Коротко

| Куда идём | Потолок Windows | Статус |
|---|---|---|
| Остров-оверлей с точечной графикой | свой рендер, ограничений нет | ✔ сделано |
| Акцент из обоев | чужой файл обоев читается, система перекрашивается через DWM | ✔ сделано |
| Тёмные заголовки всех окон | DWM, официальный вызов | ✔ сделано |
| Свои курсоры | реестр `Control Panel\Cursors` + `SPI_SETCURSORS` | ✔ сделано |
| Монохромные иконки ярлыков | поле `IconLocation` у `.lnk` | ✔ сделано |
| Поиск программ и файлов | своя индексация, системный поиск закрыт | ✔ сделано (3 папки, 2 уровня) |
| Перечисление значков трея | **публичного API нет** | ~ по владельцам окон |
| Эквалайзер системного звука | WASAPI loopback — одно устройство | ~ с оговоркой |
| Громкость эквалайзером по приложениям | нужен APO-фильтр (Equalizer APO) | ☐ нет |
| «Заплывание» обоев на окна | только поверх окон, глубоко — нет | ☐ нет |
| Замена explorer.exe | возможно, но опасно | ☐ отложено |

## Где Windows не мешает

**Оверлей.** WPF-окно с `AllowsTransparency` даёт попиксельную прозрачность: остров
рисуется на своём слое, клики мимо него проходят в приложения под ним. Всё точечное
(часы, текст, обложки, эквалайзер, циферблат, уведомления) рисуется одним движком
`DotGrid` — картинок в архиве нет, поэтому акцент меняется без пересборки ассетов.

**Оформление.** Тёмные заголовки — `DwmSetWindowAttribute` с
`DWMWA_USE_IMMERSIVE_DARK_MODE`, официально и обратимо. Акцент Windows — чтение
`ColorizationColor` из DWM и запись `AccentColor`/`AccentPalette` в реестр с
broadcast-сообщением. Курсоры — `HKCU\Control Panel\Cursors`, с сохранением оригиналов
и откатом.

**Медиа.** Системный SMTC даёт трек, исполнителя, обложку и прогресс для любого плеера,
который его поддерживает. Перемотка — `TryChangePlaybackPositionAsync`; ограничение одно:
не все плееры её реализуют.

**Оболочка.** Трей на `Shell_NotifyIcon` — обычный Win32: скрытое окно-приёмник,
`TaskbarCreated` для перезапуска проводника, пузырь через `NIF_INFO`. Меню трея сделано
своим окном, а не WPF-попапом: попап с `Shell_NotifyIcon` не держится, потому что у
скрытого окна нет нормальной активации (проверено дважды).

## Где упираемся (и что сделано вместо)

### 1. Значки трея перечислить нельзя

API «дай все значки в области уведомлений» не существует. Что делаем: перебираем
**скрытые окна-приёмники** с классами вида `*Tray*`, `*NotifyIcon*` и читаем их процессы.
Отсюда ограничения:

- приложение с «неправильным» классом окна не найдётся (Chrome, WPF-программы);
- значки в переполнении (`TopLevelWindowForOverflowXamlIsland`) недоступны;
- два значка одного exe схлопываются в один.

Полный обход — чтение `ToolbarWindow32` чужого процесса через `ReadProcessMemory`.
Ломается обновлениями Windows, поэтому лежит отдельной задачей с пометкой «хрупко».

### 2. Эквалайзер видит только одно устройство

WASAPI loopback снимает **выбранное** устройство вывода. Музыка играет в наушниках, а
«по умолчанию» колонки — спектр получает тишину. Сделано: выбор устройства в настройках
и перезапуск захвата при смене (0.51). Не сделано: авто-выбор устройства, которое реально
играет.

### 3. Громкость по приложениям

Громкость каждого приложения Windows отдаёт (`IAudioSessionControl`), а **фильтры**
(эквалайзер) на чужой поток — только через APO, а APO требует драйверного уровня
(Equalizer APO). Обход уже есть: аудио-роутер отправляет приложение на выбранное
устройство (0.37) — в большинстве случаев этого достаточно.

### 4. Обои, «заплывающие» на окна

Обои можно положить поверх рабочего стола, но не «за окна и между ними»: композитор
Windows не отдаёт такой слой. Реалистичный максимум — свои обои на столе плюс акцент из
них (это и сделано). Полноценные живые обои — отдельный продукт (Lively); интегрироваться
с ним можно, подменить собой — нет.

### 5. Замена explorer.exe

Технически возможно: прописать свой exe как оболочку, поднять панель задач, обработать
`TaskbarCreated`. Практически — один неудачный старт оставляет пользователя без панели
задач. Поэтому это последний этап плана со статусом «опционально»: сначала надёжный путь
отката и понятная кнопка «верни как было».

## Что из этого следует

1. Всё, что не упирается в чужие потолки, делается своими руками — и уже делается.
2. Упираемся в двух местах: значки трея и фильтры звука. Оба обходим частично и
   **обозначаем ограничение в интерфейсе**, а не делаем вид, что всё работает.
3. Замена оболочки — не фича, а последний шаг с отдельным риском. Туда идём, когда
   остров, поиск и трей станут ежедневно надёжными.

Актуальный план — [ROADMAP.md](../ROADMAP.md). Ограничения, с которыми живём сейчас, —
[TROUBLESHOOTING.md](TROUBLESHOOTING.md).
