# DOT SHELL — можно ли это построить на Windows?

> Разбор идеи: Nothing-эстетика (точки), «остров» сверху монитора, лаунчер,
> буфер обмена за сессию, заметки, эквалайзер, интерактивные обои с авто-цветом
> и «заплыванием» на окна, кастомизация уровня Linux-райсинга — но без боли в настройках.

**Короткий ответ: да, это реально и технически выполнимо почти целиком.**
Но это **не одна программа**, а небольшой «комбайн» из 5–6 модулей, живущих рядом.
И есть 3 места, где ты упрёшься в потолок самой Windows — про них честно ниже.

---

## 0. Сначала — как это вообще называется

| Твоё слово | Правильное название |
|---|---|
| «лаунчер или тема» | **Desktop shell / shell-оверлей** (оболочка поверх Windows) |
| «остров как у айфона» | **Dynamic Island** / floating HUD / top-center capsule |
| «точки как у нафинга» | **dot-matrix UI**, глиф-растр 5×7, NDot-подобный шрифт |
| «настраивать как в линукс-дистрибутиве» | **theme packs / ricing**, конфиг = один файл |
| «заплывание обоев на окна» | **wallpaper bleed / desktop compositing overlay** |
| «подцепить плеер» | **SMTC** (System Media Transport Controls) |

Жанр существует. Аналоги, которые уже делают куски этой идеи:
- **Wallpaper Engine / Lively Wallpaper** — живые обои (Lively бесплатный, open source);
- **Nohzdyve** — минималистичный лаунчер на Windows, уже в Nothing-стиле;
- **Rainmeter** — виджеты на десктопе (старьё, но живое);
- **Windhawk** — инжект в explorer.exe/dwm, меняет поведение самой системы;
- **Ditto / Windows+V** — история буфера обмена;
- **Flow Launcher / PowerToys Run** — лаунчер с плагинами;
- **Equalizer APO + Peace** — системный эквалайзер;
- open-source Dynamic Island для Windows: `warpirate/pillar-dynamic-island-for-windows`,
  `adityasrivastava5098/WinIsland`, `MoFeng2223/BrimDeck`.

**Вывод: по отдельности всё это уже есть. Никто не собрал это в одну «ламповую»
Nothing-систему с единой темой и единым островом. В этом и есть ценность идеи.**

*(Про CMF: да, CMF by Nothing — дочерний бренд, и у них та же дизайн-языковая база:
точки, монохром, один акцентный цвет, «индустриальная» типографика. То есть референс
ты назвал точно — это ровно тот визуальный язык, который тут разбирается.)*

## 1. Разбор по фичам: реально / сложно / невозможно

### 🟢 Остров сверху по центру — **легко, делается за дни**
Окно `WS_EX_LAYERED | WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`,
позиция = центр верхнего края монитора (`MonitorFromWindow` + `GetMonitorInfo`), без рамки,
клик не ворует фокус. Анимация расширения — средствами XAML/Composition.
Нюанс: не перекрывать «чёлку» камеры на ноутбуках — отступ настраиваемый.
**Вердикт: 10/10.** В скелете уже реализовано (`IslandChrome.cs`).

### 🟢 Плеер внутри острова — **легко**
`GlobalSystemMediaTransportControlsSessionManager` — один API даёт: что играет,
артист, альбом, обложка (битмап), позиция, команды play/pause/next/prev/seek.
Работает со Spotify, YouTube в браузере, Apple Music, foobar2000, VLC — со всем,
что зарегистрировано в SMTC.
**Вердикт: 10/10.** Реализовано (`Media/MediaBridge.cs`).
Обложка приходит растром — для точечного вида её надо пикселизировать (16×16 → точки).

### 🟢 Буфер обмена «всё за сессию» — **легко**
`AddClipboardFormatListener` → ловим каждое изменение → разбираем форматы
(текст, bitmap, список файлов) → складываем в историю.
Горячая клавиша → попап с поиском → двойной клик = положить в буфер и нажать Ctrl+V.
Плюсы перед встроенным Win+V: неограниченная история, fuzzy-поиск, пины,
режим «только до перезагрузки», превью картинок.
**Вердикт: 10/10.** Реализовано (`Clipboard/`).

### 🟢 Заметки — **легко**
Markdown-файл в `%LOCALAPPDATA%\DotShell\notes.md` + автосохранение.
Специально файл, а не база: его можно открыть в любом редакторе и синхронизировать.
**Вердикт: 10/10.** Реализовано.

### 🟢 Лаунчер — **легко, но есть нюансы**
Индекс: `.lnk` из Start Menu (`IShellLink`), UWP-пакеты (`Windows.Management.Deployment`),
файлы (индекс Windows Search), калькулятор, команды. Fuzzy-поиск — тот же алгоритм,
что уже написан для буфера обмена (`InMemoryClipboardHistory.FuzzyScore`).
Нюанс: иконки приложений надо **перерисовывать в точечный стиль**, иначе эстетика сломается.
Это делается тем же `DotGrid.Sample`: битмап иконки → сетка 8×8 → точки.
**Вердикт: 9/10.** Не изобретай с нуля — можно форкнуть Flow Launcher и написать ему
свою тему, это экономит месяц.

### 🟢 Точечная эстетика (главная изюминка) — **легко, это просто графика**
Нужен рендерер «что угодно → сетка точек»: растеризуешь текст/иконку/арт,
сэмплируешь по сетке, каждую живую ячейку рисуешь кружком.
**Вердикт: 10/10.** Реализовано (`DotMatrix/DotGrid.cs` + `Controls/DotTextBlock.cs`).
Шрифт: **NDot — проприетарный шрифт Nothing**, в продукт его брать нельзя.
Варианты: сделать свой dot-шрифт (2–3 вечера в FontForge) или использовать свободные
dot-matrix/сегментные шрифты. **Это юридический вопрос, а не технический.**

### 🟡 Авто-цвет из обоев — **легко алгоритмически**
Кадр → downscale до 64×64 → отбросить серое/чёрное/белое → корзины по оттенку →
победитель = количество × насыщенность → довести насыщенность → сгладить (EMA).
Это и есть ответ на «не запарно в настройках»: **настроек почти нет — тема собирается
сама из обоев.** Одна кнопка «Auto» + 6 пресетов + ручной оверрайд.
**Вердикт: 10/10.** Реализовано (`Theming/ColorExtractor.cs`, `AccentSampler.cs`).
Плюс `tools/theme_from_image.py` — тот же алгоритм на Python, чтобы экспериментировать.

### 🟡 Кастомизация «как в линукс-дистрибутивке» — **реально, но это архитектура**
Линукс-райсинг работает, потому что всё — конфиги. Значит и здесь:
```
themes/nothing-red.json   (потом .zip)
├── colors      // акцент, фоны, рамки, текст
├── dot         // размер точки, зазор, порог, «погасшие» точки
├── motion      // длительности и кривые анимаций
└── widgets     // что в свёрнутом острове, какие вкладки, какие хоткеи
```
Один файл = вся тема. Импорт/экспорт/шаринг, live-preview.
**Вердикт: 10/10, но закладывать с первого дня.** Формат уже описан (`Theming/ThemeSpec.cs`),
чтение/применение темы — первая задача Фазы 2.

### 🟡 Интерактивные обои — **реально, вопрос цены**
Два пути:
1. **Не писать свой движок.** Lively Wallpaper умеет HTML-страницы и шейдеры как обои,
   бесплатный, open source, и уже решает самую грязную часть — внедрение в десктоп.
   Твоя программа отдаёт ему тему и управляет им по IPC.
2. **Свой рендер.** DirectX 11/12 (Vortice.Windows) или WebView2, рисующий в окно,
   вставленное в иерархию `Progman → WorkerW` (классический трюк, на нём стоят
   Wallpaper Engine и Lively).

**Подводный камень:** Microsoft в сборках Win11 26xx ломала этот трюк — Lively чинили его
внедрением layered-окна между слоем иконок и слоем обоев. То есть **каждый крупный апдейт
Windows может что-то сломать.** Закладывай fallback на «просто картинка/видео как фон».
**Вердикт: 8/10.** Работает, но это самая хрупкая часть относительно обновлений ОС.

### 🟡 «Заплывание» обоев на другие окна — **самая сложная фича, но выполнимая**
Прямого API нет: DWM не даёт «подмешать» твой контент в чужое окно. Три рабочих схемы:

**A. Прозрачный оверлей-слой поверх окон с «дырками» (то, что ты описал).**
Рисуешь обои ещё раз в окне, которое лежит **выше обычных окон, но ниже активного/топмоста**,
и вырезаешь в нём регионы по прямоугольникам окон.
- Прямоугольники: `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` + `EnumWindows`,
  обновление по `EVENT_OBJECT_LOCATIONCHANGE` (WinEvent hook) — надёжно и дёшево.
  В скелете уже есть `WindowWatcher.TryGetExtendedBounds` — именно для этого.
- Прозрачность: per-pixel alpha (`UpdateLayeredWindow`) или Composition + mask.
- «Игры и fullscreen не трогаем»: foreground-окно, сравнение его rect с rect монитора,
  плюс `DWMWA_CLOAKED`. Уже реализовано (`WindowWatcher.CheckFullscreen`).
  Exclusive-fullscreen игры вообще уводят DWM в сторону — там слой просто не виден.
- **Цена:** перерисовка большой площади каждый кадр = реальные миллисекунды GPU
  и заметное энергопотребление. Плюс артефакты при быстром перетаскивании окон (лаг на кадр).
- **Митигация:** 30 fps cap, только видимые окна, отключение при batterysaver, whitelist.

**B. Не «заплывать», а «подсвечивать» (дешёво и почти так же красиво).**
Тонированные полупрозрачные подложки у **своих** окон (`DWMWA_SYSTEMBACKDROP_TYPE`)
+ тонкая цветная кромка/свечение вокруг чужих окон. Свечение — один тонкий оверлей
по периметру rect'а окна, это копейки по производительности.

**C. Инжект в чужие окна (как «window effects» у Wallpaper Engine).**
Максимально эффектно, но: антивирусы ругаются, часть приложений (anti-cheat, DRM,
браузеры с hardware-protect) сломается, поддержка — ад.
**Вердикт: 7/10.** Начни с B, потом делай A как «experimental» режим с явным тумблером
«эффект может жрать батарею». **C не делай** в первой версии.

### 🔴 Системный эквалайзер — **тут потолок Windows**
Свой системный эквалайзер = написать и зарегистрировать **APO** (Audio Processing Object).
Это COM-объект, driver-подобная регистрация, подписи, боль.
**Правильный ход: не писать движок, а сделать красивую Nothing-морду к Equalizer APO**
(бесплатный, open source, системный): твоя программа генерирует его `config.txt`
и читает пресеты. Получаешь «свой эквалайзер» в своём дизайне за неделю вместо полугода.
**Честное ограничение:** DRM/protected audio streams (часть сценариев Spotify)
системные эквалайзеры **не обрабатывают** — это политика ОС/приложения, а не баг.
Надо показывать плашку «это приложение защищено, EQ недоступен».
**Вердикт: 6/10 своими силами / 9/10 через Equalizer APO как бэкенд.**

### 🔴 «Тема» для всей Windows — **главный облом**
В Windows **нет** публичного механизма темизации, как в Linux (GTK/Qt-темы).
- `.msstyles`-темы требуют патча `uxtheme.dll` (UltraUXThemePatcher) → **неподписанные
  системные файлы, ломается при каждом апдейте.** Не рекомендую.
- Системную подстановку шрифта можно сделать реестром (FontSubstitutes), но это
  **глобально и опасно**: точечный шрифт в диалоге «Удалить всё?» — это плохо.
  Лучше: точечный шрифт **только в твоих поверхностях** + опционально в заголовках окон.
- Что **реально можно** без патчей системы:
  - тёмные тайтлбары своих окон — `DWMWA_USE_IMMERSIVE_DARK_MODE` (легально);
  - **Windhawk-моды** — инжект в `explorer.exe`/`dwm.exe`, меняют поведение системы
    (скругления, анимации, скрытие элементов). Рабочий и популярный путь, но это
    DLL-инжект → антивирусы косятся, и это внешний инструмент, не твоя программа;
  - иконки проводника частично заменяются через icon handler / кастомные `.lnk`.

**Реалистичная стратегия «райсинга» на Windows:**
- **70%** — свои поверхности (остров, лаунчер, панели, обои, виджеты) в идеальном Nothing-стиле;
- **25%** — интеграция (тёмные тайтлбары, единый акцент в трее, курсоры, звуки);
- **5%** — опциональный «deep mode» через Windhawk-мод, который пользователь ставит сам.

**Вердикт: 3/10 для «перекрасить всю Windows». 9/10 для «перекрасить всё, что ты видишь
постоянно».** Полной «темы ОС» не будет, но будет ощущение цельной системы, потому что
90% времени глаза смотрят на десктоп, обои, остров и лаунчер.

## 2. Архитектура

**Главная ошибка, которую легко совершить:** писать монолитное GUI-приложение.
Оно падает целиком, жрёт память и его невозможно развивать.
Правильно — **ядро + плавающие модули**:

```
┌─────────────────────────────────────────────────────────────┐
│  DOT SHELL CORE  (один процесс, .NET, без UI, живёт в трее) │
│  ── Theme Bus: акцент/палитра/плотность точек (pub-sub)     │
│  ── Settings Store: JSON + SQLite, атомарная запись         │
│  ── Wallpaper Color Extractor (кадр → палитра → авто-тема)  │
│  ── Window Watcher: fullscreen-детектор, границы окон       │
│  ── Media Bridge: SMTC-сессии → события плеера              │
│  ── Clipboard Watcher → история                             │
│  ── Hotkey Manager (RegisterHotKey)                         │
│  ── Perf Governor: fps-капы, пауза, batterysaver, whitelist │
│  ── IPC (named pipes) для модулей                           │
└──────────────┬──────────────────────────────────────────────┘
               │  (каждый модуль — отдельный процесс, падает сам по себе)
   ┌───────────┼───────────┬───────────┬───────────┬───────────┐
   ▼           ▼           ▼           ▼           ▼           ▼
 ISLAND    LAUNCHER    WALLPAPER    CLIPBOARD    NOTES       EQ SKIN
 (WinUI3,  (WinUI3     (Lively/     (попап у     (панель,    (морда к
 topmost,  или WebView  свой DX-     курсора,     .md файлы)  Equalizer
 layered)  + хост)      рендер)      topmost)                 APO)
```

Почему так:
- **Изоляция отказов.** Упал рендер обоев — остров и лаунчер живут.
- **Перформанс.** Тяжёлый рендер не тормозит UI острова (остров обязан держать 60 fps).
- **Обновляемость.** Новый модуль выпускается без переустановки всего.
- **Память.** Выключенные в теме модули просто не запускаются.

> В текущем скелете ядро и остров живут **в одном процессе** — так проще отлаживать,
> пока модулей два. Разделение на процессы нужно, когда появится третий тяжёлый
> (обои или лаунчер). Место для этого уже приготовлено: весь доступ к ядру идёт
> через `ShellServices`, а не напрямую, поэтому разъехать на процессы можно без переписывания UI.

### Стек

| Слой | Технология | Почему |
|---|---|---|
| Ядро + UI | **C# / .NET 8 + WinUI 3 (Windows App SDK)** | один язык на всё, нативный доступ к SMTC/WinRT, Composition API, Mica/Acrylic |
| Win32 | **P/Invoke** (в скелете написан руками, дальше можно CsWin32) | не писать объявления каждый раз |
| Точечный рендер | сейчас CPU + `WriteableBitmap`, дальше **Win2D / pixel shader** | CPU хватает для часов и обложек, для обоев нужен GPU |
| Обои | **Lively Wallpaper** (внешний движок) → позже свой DirectX | не изобретать WorkerW-трюк и его починки |
| Хранение | JSON сейчас, **SQLite** для истории буфера и заметок | один файл, транзакции, полнотекст |
| Хоткеи | `RegisterHotKey` | официально, без хуков |
| Эквалайзер | **Equalizer APO** как бэкенд, свой скин | не писать APO |
| Глубокая темизация | **Windhawk-мод** (опционально, отдельно) | единственный вменяемый путь |
| Упаковка | **MSIX** или Inno Setup + авто-апдейт | чистая установка |

**Альтернатива:** Tauri 2 (Rust + web-UI) — меньше памяти, красивые анимации на CSS,
но SMTC/WinEvent/DWM всё равно через FFI, а живые обои в WebView — дорого.
Electron — **нет**: 300–500 МБ ради острова в режиме 24/7 это позор.

### Ориентиры по ресурсам (цель, которую надо держать)
- память в режиме 24/7: **< 250–350 МБ** без живых обоев, **< 600 МБ** с обоями;
- CPU в простое: **< 1%**. Остров не должен тикать чаще раза в секунду, когда ничего не происходит;
- обои: **cap 30 fps**, пауза при закрытом десктопе, стоп в fullscreen.

## 3. Риски — честно

| Риск | Боль | Что делать |
|---|---|---|
| Апдейты Windows ломают WorkerW / недокументированное | 🔴 | опираться на Lively (они чинят), иметь fallback на статичный фон |
| Антивирус ругается на DLL-инжект | 🟡 | не делать инжект в ядре продукта; вынести в отдельный опциональный мод, подписывать бинарники |
| Невозможно перекрасить всю систему | 🟡 | принять и продавать «цельность того, что ты видишь», а не «тему ОС» |
| DRM-аудио не пропускает эквалайзер | 🟢 | понятная плашка в UI, не баг |
| NDot — чужая интеллектуальная собственность | 🟡 | свой dot-шрифт или лицензия |
| Жор батареи/VRAM обоями и оверлеем | 🟡 | perf-губернатор с первого дня |
| Multi-monitor + разный DPI + масштаб 125/150% | 🟡 | тестировать на двух мониторах с разным DPI сразу, иначе потом переписывать layout. В скелете точки специально считаются в физических пикселях |
| «Заплывание» лагает на кадр при драге окон | 🟢 | интерполяция позиций, опрос WinEvent 60 Hz |
| Выгорание автора-одиночки | 🔴 | каждая фаза должна приносить удовольствие сама по себе; открыться на GitHub |

## 4. Что делает это «ламповым и незапарным»

Ты правильно сформулировал главное противоречие: **райсинг = много настроек,
а ламповость = настроек нет.** Разрешается так:

1. **По умолчанию всё само.** Поставил → выбрал обои → тема собралась сама
   (акцент, плотность точек, свечение, иконки). Ноль кликов.
2. **Настройки — это не 100 слайдеров, а 6 пресетов + одна кнопка «Auto».**
   Продвинутое спрятано за «Advanced», но оно есть — райсеры оценят.
3. **Тема = файл.** Кинул другу `nothing-amber.zip` — у него идентично.
   Это и есть «как в новой линукс-дистрибутивке», только без конфига на 400 строк.
4. **Один остров на всё.** Не 15 виджетов на десктопе, а одна точка входа,
   которая раскрывается в то, что нужно сейчас. Минимализм = не «мало функций»,
   а «мало видимого одновременно».
5. **Всё дышит в одном ритме:** одна и та же точечная сетка в часах, иконках, обложке,
   эквалайзере, курсоре загрузки. Вот это считывается как «оформление Nothing»,
   а не просто красный акцент.

---

## 5. Итоговый вердикт

- **Написать можно.** Это не «изобрести новый Windows», это сборка из известных API:
  SMTC, clipboard listener, WinEvent hooks, DWM-атрибуты, layered windows, SQLite.
- **~85% задуманного реализуемо полностью**, ~10% (глубокая темизация чужих приложений) —
  частично и через костыли типа Windhawk, ~5% (свой системный эквалайзер, DRM-аудио) —
  только через чужой бэкенд или никак.
- **Самое сложное — не код, а дисциплина:** единая тема между модулями,
  производительность 24/7 и живучесть после апдейтов Windows.
- **Самая рискованная фича — «заплывание» обоев.** Делать последней и за тумблером.
- **Самая ценная часть идеи — не фичи, а цельность.** Куски уже существуют;
  никто не склеил их в одну Nothing-систему. Это и есть продукт.
